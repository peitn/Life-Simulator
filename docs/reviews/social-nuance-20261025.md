# H5 social nuance, trust, emergent dependence and private care — 25 October 2026

**Source of truth:** live Godot `lifesim`. User explicitly asked for implementation, not a proposal. The earlier eight-person fictional test inspired three changes: not every failed conversation is an argument; trust/long-term interpersonal reliability differs from liking; and attachment/dependency can emerge and affect social vulnerability. They also asked why SH was absent. This is a *non-graphic, supportive, privacy-preserving* treatment, not automatic self-harm simulation.

## Implemented source changes
1. `scripts/sim/sim_agent.gd` and `scripts/sim/action_library.gd`: normal autonomous conversations now resolve to **chat, genuine argument, awkward fade-out, or misunderstanding**, with labels and original authored bubble phrases. About 36% of otherwise unsuccessfully sampled conversations are split between awkwardness and misunderstanding. These are milder: no ordinary fight memory or symmetric 8-point grudge / high fight stress. `conversation` includes `outcome` and explicit `argued`, while existing `success` remains supported. Forced player `insult` remains a conflict and unchanged. De-escalation remains effective.
2. `scripts/sim/household_dynamics.gd`: new `stats.outcomes` histogram, `argues`, `by_mood` and `complaint_argues` now count **only actual arguments**. Previous v1 saved dynamics dictionaries lacking the new histogram initialize it safely on first new conversation; world state is never silently modified by the save validator. Successful conversations and shared moments build separate private trust alongside liking.
3. `scripts/sim/rel_ledger.gd`: directional `trust` (neutral baseline45/100), independent of liking and of pre-existing `attachments`. Compact bounded `relational_history` counts warm, hurt, awkward, misunderstanding, repair, support, dismissed events, beyond the last40 text memories. Repeated harm reduces trust; accepted apologies repair partly and broken previous apologies reduce the credit. `from_dict` validates fields, keeps missing optional fields backward-compatible, and preserves sparse counters EXACT on serialize/reload. Trust values and compact histories remain private.
4. Same ledger adds `learn_attachment`, called by `SimAgent._learn_connection` after positive conversations/accepted support and by real household shared moments. Positive repeated ties may strengthen person-specific *importance* and *dependency* if social desire and rejection sensitivity are high; a diverse set of reliable bonds reduces concentration. No love/affection = automatic dependency; reciprocity is not guaranteed. Dependency can gradually subside. The pre-existing `_on_rejection_cue` already uses `attachment_to(...).impact`, so learned dependency now affects how personally important a perceived/actual rejection is, **without making the perceived cue factual**. This is a behavioral feature, NOT a diagnosis.
5. `scripts/sim/utility_planner.gd`: `confide` target attractiveness now depends on earned trust as well as liking; low trust does **not** hard-block player or AI agency.
6. `scripts/sim/sim_agent.gd` private attachment labels distinguish **forming emotional dependency** at0.12, increased at0.40, strong at0.75 and optionally earned trust/distrust. Existing `scripts/ui/hud.gd` already shows `private_attachment_labels` only for offline owner. HUD now also shows a **private offline qualitative support hint**. Severe concurrent depressive burden and stress can flag `support_needed` independently of actual SH concern. These are not medical predictions.
7. SH: `RejectionResponse` already tracked a non-graphic private `safety_concern` under **full mental-health + explicit `sh_ed_topics=true`**. Eight-person prior fixtures explicitly disabled it. The new offline HUD hint makes opt-in concern visible when present, but NO automated SH action, injury methods, reward, diagnosis, forced outcome or network disclosure was created. Generic severe strain can request support even when SH is OFF without conflating depression with SH. The existing strictly manual offline opt-in `present_implied_sensitive_incident` with complete visual obstruction is **unchanged** and not spawned by the AI. This is intentional: distress does not mechanically force an injury.

## Scope, constraints and follow-ups
- New private trust/dependency and care context are not placed in public `_build_detail` or CharacterData public appearance snapshots. Existing net_detail carries pre-existing mental data via authenticated owner-private RPC; new fields are not replicated there.
- Offline HUD shows private care and relationship labels; **actual rendered UI screenshot still unverified**. Multiplayer host/H4 persistence remains explicitly unsupported. No new medical conditions were invented, no SH behavior/graphic representation added, no self-harm mechanism added to Utility AI.
- The richer conversation outcomes lower measured `argue_rate`, so historical comparisons must **not equate old binary failures with new actual arguments**. True long-range social realism, rupture/repair dynamics, attachment stability over months and support availability remain to be tested.
- Only shared v3 MAIN writer scope was used. No city, Blender, GitHub, or AI room mutations. Final backup/lock release below in main checkpoint.
