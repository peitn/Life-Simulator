# Review: crowd LOD step 6 – baking blend shapes at tier 2 (18 Nov 2026)

## What
- `scripts/assets/lod_bake.gd` (new): sparse per-key deltas (built once per source mesh, cached via weak refs) and `bake(source, weights)` that produces a static `ArrayMesh` with the current blend-shape result applied (`base + Σ w·(target − base)`, i.e. Godot's NORMALIZED mode with absolute targets as written by HeadBuilder/HairRig). Normals and tangents are summed and renormalised; UVs, bones/weights, CUSTOM0, colours, indices, automatic LOD index buffers, materials, surface names and the surface format are preserved.
- `scripts/sim/sim_visual.gd`: at crowd tier 2, after 0.4 s of rest, every visible mesh instance with blend shapes (hands excluded – the finger-pose API reads and writes weights) is swapped for its baked mesh. The job runs on `WorkerThreadPool`; the main thread only collects weights and swaps meshes. Any change of weights or meshes (`apply_look`, face/body shape, forced expression, hair/wardrobe mesh swaps) calls `_lod_touch()`, which restores the original meshes with their exact weights and schedules a new bake. Leaving tier 2 restores the originals. Stale jobs are discarded via a generation counter.

## Why
A random character at tier 2 had ~45 active keys on the head (6,350 vertices), 5 on each eye part, 9 on the lashes, 18 on the hair proxy, 8 on the body plus garments. Expressions are frozen at tier 2, but the GPU still re-blends every non-zero key each frame because skinning invalidates the result. After baking only skinning remains.

## Measurements (headless server, no GPU timing available)
- Head: cold source build ~390 ms (once per session, worker thread), bake with cached deltas ~12 ms.
- Whole character job 33–190 ms on a worker; main thread: start 0.3–0.5 ms, restore 0.5–0.9 ms.
- Identical weight vectors share one baked mesh (weak-ref cache).

## Tests
`tests/test_lod_bake` 54/54: dense-formula accuracy (synthetic and real head, error 0 m), unit normals, tangent sign, all other arrays unchanged, LOD index content identical, materials/Skin/skeleton of instances unchanged, bake only after rest, no repeated bakes, exact weight restore at tier 0, rebake after `apply_look`/`set_expression`, stale job discarded, node freed during a job, disabled switch, cache pruning.

## Audit
Gemini 2.5-flash: accepted – dead entries in the baked-mesh cache were only pruned on new sources (now every 32 stores, tested). Rejected with evidence – LOD decoding (test compares index content bit for bit), dictionary cleared after the loop (code clears after iteration), `is_instance_valid` (present; the review saw a summary). Known: the cold `raw_of` copy runs on the main thread once per source mesh.

## Not verified
No GPU frame-time measurement (no display/xvfb on the server); the benefit is argued from Godot's per-frame blend-shape pass, not measured.
