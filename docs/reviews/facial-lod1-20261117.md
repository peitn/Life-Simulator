`SimVisual` swaps brows and beard meshes together with the scalp in `_apply_hair_lod()` when the tier changes
(full mesh at tier 0, LOD1 at tier ≥ 1; at tier 2 the parts are hidden, so 1 ↔ 2 never swaps meshes) and rewrites the
shape-key weights right after the swap. The lookup `HairRig.cached_facial_lod1()` never builds anything, so the
visual never blocks; LOD1 is built in the same worker task as the full mesh.

## Bug found in the fallback version: density

The hair shader hides facial cards whose strand random `CUSTOM0.x` is above the per-character `density`
(brow / facial-hair density sliders, 0–1). Meshes are shared per style, so the LOD reducer cannot know the density.
The fallback kept cards with `x < 0.425` and widened them 1.5× regardless of density:

* density 0.3 → LOD1 still showed *every* visible card, now 1.5× wider — thin brows got denser with distance;
* density 1.0 → only 42.5 % of the cards remained.

Fix: kept cards get `x' = min(x / keep, 0.9999)`. At any density `d`, LOD1 shows exactly the full-mesh cards with
`x < keep · d` — a nested subset of what tier 0 shows, with a constant ratio. `test_facial_lod1` checks this exactly
for six densities and all styles, and includes a sensitivity check (without the rescale, dense brows at d = 0.3
would keep 1.00 of their visible cards; with it 0.52).

## Choices and measurements

* **No outline protection for eyebrows.** The outline grid (angular cells around the head centre) marks almost every
  brow card, because brows are a 1–2 mm layer on the skin; five of six styles then fell under the 20 % saving
  threshold and got no LOD1. Brows do not shape the head silhouette, so the protection is off for them. Beards keep
  it (a full beard changes the jaw profile).
* **Full widening for the face (1 / keep, cap 2.5).** The scalp uses 1/√keep capped at 1.5 because wider cards read as
  coarse bands on long hair. In tier 1 the face is roughly 10–30 px tall and a facial card (3–5 mm) is below one
  pixel, so what matters is how much the hair darkens the face. Summed darkening in the CPU render, LOD1 / full:
  with 1/√keep 0.64–0.89 (thin brows + chin beard at density 0.3 visibly lighter), with 1/keep 0.87–1.07.
* **Explicit keep for beards (0.425).** Previously derived from the card layer via `lod1_keep(c0.z)`; all facial
  cards use layer 0.5, so the value is the same, but a future builder change would have silently changed the LOD
  (Gemini review finding, accepted).
* **Moustache excluded.** With 138 triangles the saving is 33 triangles, and the few remaining widened cards gave a
  front coverage of 1.34× the full mesh. Below 300 triangles a LOD1 is not worth it.

## Verification

* `tests/test_facial_lod1.tscn` — geometry for every style (savings, compact vertices, valid indices, finite values,
  `CUSTOM0.x` in [0, 1), skin weights summing to 1, identical blend-shape names/order/format), skip reasons in
  `build_stats`, exact density nesting, binomial 3σ ratio check, front coverage, far-distance darkening, strongest
  blend shape still moves LOD1 by a similar amount, byte-identical rebuild after `clear_cache`, concurrent builds in
  `WorkerThreadPool` equal to sequential ones, `SimVisual` tier switching (meshes, weights, material density
  unchanged, shadows off, style changes at tier 1, moustache falls back to the full mesh, switch cost < 2.5 ms),
  `cached_facial_lod1` does not build, async build at tier 1.
* CPU render without a display: `tools/render_facial_lod1_cpu.tscn` →
  `previews/facial-lod1/cpu_sheet.png` (rows: dense brows + full beard d 0.6, thin brows + chin beard d 0.3, joined
  brows + sideburns d 1.0, arched brows + moustache d 0.6; columns full/LOD1 front and ¾). The image could not be
  inspected by eye in this run (no display on the server, the Blender bridge returned 503); the comparison was done
  numerically on the rendered pixels (coverage and darkening, see above).
