# H4 offline persistence and autosave — 2026-10-25

**Implementation status:** real working **offline-first** H4 slice in Godot `lifesim`; full H4 / multiplayer persistence remains **PARTIAL**. Source of truth is live Godot, not the stale GitHub repository. User directly asked for save/load and automatic saving.

## User-facing behavior
- Regular GUI offline game automatically loads the **autosave** on launch if available. If primary fails checksum or shape validation, the previous **valid backup** is used; incompatible files are rejected. Missing save starts the default household.
- Automatic save every **300 seconds of real play**, even if game time is paused, **and after each game-day rollover**. Window-close notification attempts an additional autosave; a crash/forced kill cannot guarantee that last emergency save.
- HUD has `Uložit hru` (Save game), `Načíst auto` (Load autosave), `Načíst ručně` (Load manual save). Shortcuts: **F5** save manual; **F9** load autosave; **Shift+F9** load manual. Loading discards the existing offline editor's unsaved draft, avoiding writes into another incarnation of the household.
- Save files are local, not encrypted, under Godot `user://saves/`: `autosave.lss`, `manual.lss`, `*.bak` (previous valid version) and `*.invalid` (quarantined corrupt primary); `*.tmp` staging is not a valid save. Slot names are allowlisted. Never include these sensitive files in public Github assets.
- **Offline only** in this slice: listen host, dedicated server and multiplayer clients cannot call these APIs. They will require a separate server-only authoritative persistence implementation. Headless/test runs don't auto-load/autosave by default; test fixture `net_config` may explicitly opt in with an isolated `save_directory`.

## What actually persists
- Full canonical private CharacterData, UID, appearance/wardrobe, schema-v8 identity/body/personality, revision and stable node name. V1 versioned save envelope and strict CharacterValidator verification before any destructive restore.
- Game clock (precise fractional total minutes, speed, running), selected character; all six needs and decay modifiers; active + lingering moodlets; stress, physical/pleasant/aversive arousal, depression's wanting/liking/vigour and adaptation, panics/cooldowns/times/thoughts; coping logs, vulnerability, vigilance, rejection and sensory habituation; ledgers of grudges/guilt/attachments, relationships, conversations, memories, recent actions, moods and current tasks/targets/elapsed durations/command queue. In-flight target and queued references are serialized by stable agent node name or smart-object index. Object reservations restore after all agents are recreated.
- Full per-character **RandomNumberGenerator.state** and household dynamics accumulators/timestamps/stats, which is necessary for deterministic continuation after a reload. No public multiplayer replication of these private saved payloads.
- World geometry currently remains the existing fixed starting lot, not a built/edited city. No future construction state is claimed.

## Format and failure handling
- `scripts/save/game_save.gd`: byte-serialized Variant dictionary with `MAGIC=LS-HOUSEHOLD`, version1, bounded max 8MiB payload, SHA-256 payload checksum, `bytes_to_var` *without arbitrary Object instantiation*. Strict preflight checks roster, canonical character validity, finite clock, typed/finite locations, known reference targets, bounded needs/mood, lot identity, occupant capacity, etc.
- Stage a `.tmp` write, flush and **re-read/verify** prior to replacing primary. Rotate existing *valid* primary to `.bak`; a corrupt/temporarily unreadable primary is **quarantined**, not deleted. File renames occur within the same directory, with rollback attempts when replacement fails. This is best-effort staged replacement with recoverable backup; not a claim of a power-loss-proof filesystem transaction or universal `fsync` portability.
- `GameSave.apply` validates the full snapshot before discarding current offline household, rebuilds canonical Sims (not client puppets), restores references and reserved objects in two passes and restores clock after agent initialization. Invalid snapshot is rejected before mutation. Actual spawn/runtime failure after successful preflight isn't fully transactional in v1.
- `MentalState.to_dict/from_dict` extended to capture episodic/panic/thought/coupling timing; old standalone `MentalState` input remains compatible (unset keys default safely).
- `main.gd` handles auto-resume/scheduling/shortcuts/close; `scripts/ui/hud.gd` adds actual 3 save/load buttons and resets stale edit UI upon successful load.
