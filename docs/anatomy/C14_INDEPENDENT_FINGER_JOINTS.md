# C14 — Individual proximal/distal finger-bend controls (27 October 2026)

This milestone directly improves C12's ten individual whole-digit curls: a finger no longer has only **one combined bend value**. On a playable Godot skin/nail, both the knuckle-side and fingertip-side regions now have separately controllable bend channels.

## Actual playable Godot implementation
- `scripts/assets/hand_detail_builder.gd`: added **twenty new independent GPU blend shapes** (`finger_joint_{0..9}_proximal`, `finger_joint_{0..9}_distal`); original ten shape keys for public body proportion and original ten `finger_curl_{0..9}` combined keys remain intact. The actual skin mesh has 510 vertices and the matching nail mesh 90; **both now contain 40 blend shapes**. Each new joint morph only changes the selected finger, and its nail deformation uses the exact same joint transform.
- The two regions use separately weighted approximated hinge rotations: proximal ≈0.76 rad around 29% along the finger; distal ≈0.68 rad around 67% along the finger (tapered by `smoothstep`). They are **relative additive displacement GPU morphs**, NOT exact sequential rigid-body forward kinematics, collision detection or new independently dynamic skeleton bones. Strong simultaneous proximal+distal bends may differ from true anatomical joint angle composition. The 17-bone gameplay character Skin remains unchanged and remains compatible with existing 10 body morphs.
- `scripts/sim/sim_visual.gd`: new `set_finger_joint_bend(side, finger, joint, strength)` and `finger_joint_values`. Ranges are strict and finite: invalid side, digit, joint or strength is rejected without mutating skin/nail. Switching to independent-joint modes clears that finger's older whole-curl blend, and switching back clears both independent joint blends on **only that digit**, so duplicate deformations cannot accidentally accumulate. Existing `set_hand_pose` presets (open, relaxed, fist, point, pinch) retain their original shape via the combined channel, and clear advanced values.
- `scripts/ui/character_preview.gd`: under the existing collapsible **Prsty: jednotlivě** panel, new nested foldout **Klouby prstů: základní / střední** contains **20 slider controls** (proximal + distal for each of ten digits) at 0.01 precision. The original **10** combined sliders remain for quick whole-digit poses and presets. UI values clear conflicting pose controls silently (no signal loops). Camera hand zoom and the isolated `SubViewport` are preserved; no new CharacterData fields, server RPC or multiplayer edit authority.
- This remains *preview-only* custom pose editing. It is neither an owner-authorized in-world permanent gameplay hand-pose save, nor a physically simulated grasp and finger-contact model.

## Outstanding realism and limitations
Godot still draws each digit from one existing hand rig bone, with independent regional GPU deformation. **Blender** demonstrates actually separate anatomical finger bones, but these are not yet imported as separate gameplay bones with collisions/kinematic constraints. The 20 new morph targets and 28 separate Blender bones should not be described as 20 real running physical joint bodies. A next milestone would retarget Blender phalanx bones plus nail geometry into a backward-compatible separately streamed hand subrig under the 17-bone gameplay avatar, evaluate clipping on multiple morph profiles, add grasp constraints and a controlled server-authoritative interaction API.

No city-owned asset edits, no GitHub push, no sensitive character state involved.
