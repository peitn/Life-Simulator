# Life Simulator — first actual in-game anatomy integration (27 October 2026)

## What is shipped in the live Godot project

The user explicitly asked to connect previous Blender human anatomy to the **actual character in the playable game**. This version **really integrates** Blender-authored landmark positions into the production character's animated 17-bone `SimVisual` and exposes controls in both the live HUD and the existing character creator/editor preview.

- `assets/anatomy/anatomy_runtime_proxy_v1.json` — **actual exported data from the persisted editable Blender `lifesim-anatomy-skeleton-v1/anatomy_skeleton_v1.blend`**, 29,752 UTF-8 bytes. The export includes **194 named Blender anatomical bone segments** with 3D rest coordinates, driver and radius; **60 original Blender muscle bundle endpoints** and thicknesses; **60 cartilage structure centers/extents**; **six actual sculpted fat region centers/extents**. Transferred over the available connectors as a compressed GZIP, decompressed in Godot, and validated as JSON with all four expected counts. Blender/source Y-up conversion explicitly `Godot (x,y,z)=(Blender x, Blender z, -Blender y)`, matches the real production 17-bone GLB rest pose at shoulder/neck/hips/legs.
- `scripts/assets/anatomy_overlay.gd` creates a **render-only optional per-character 320-part 3D anatomical landmark proxy**, using shared materials and only **17 `BoneAttachment3D` nodes** explicitly bound to the character's existing `Skeleton3D`. It attaches every anatomical segment to its proper canonical driver bone; when the **actual gameplay skeleton animates** (idle/walk/sit/lie, posture/morph), anatomy parts follow that **same live character**, not a detached, static demonstration model.
- `scripts/sim/sim_visual.gd` implements `anatomy_available()`, `anatomy_view()`, `set_anatomy_view(mode)` for every real local in-world character. Normal in-game clothing/hair/head/body meshes are **hidden only while anatomy is showing**, with original individual visibilities restored when disabled. Normal character model, morphs, expression system, rendering and animation stay unchanged. Anatomy overlay is built **lazily** only after a user chooses it; other actors remain unaffected. Re-applying an appearance snapshot restores/resolves normal wardrobe then safely re-hides it while anatomy remains selected.
- `scripts/ui/hud.gd` has a visible **`Anatomie: Vypnuto`** (Anatomy: Off) button for the selected in-game character; each click cycles **Kostra → Svaly → Chrupavky → Tuk → Všechny vrstvy → Vypnuto** (Skeleton → Muscles → Cartilage → Fat → All layers → Off). This is client-local presentation, *never* a network character edit, savegame write, medical/psychology action or privileged RPC.
- `scripts/ui/character_preview.gd` has an independent **`Anatomie`** chooser with the same six choices for the creator/editor. It uses the already isolated SubViewport, never the live player's physics world, private identity or mind.
- **Real integration acceptance test** `tests/test_live_anatomy_overlay.tscn` / `.gd`: **76/76 PASS**. It launched a real offline `Main` with real playable household and actual 17-bone Blender `character.glb`, pressed the live HUD anatomy button, checked creation of **320 real meshes** and 17 live BoneAttachment3D drivers, manually rotated production upper-arm pose and confirmed actual anatomy attachment global basis rotated; cycled all modes, confirmed wardrobe and hair restoration, zero duplicated attachments, other resident unaffected, and separately exercised creator/editor chooser and its world isolation. Verified HUD never enters multiplayer/RPC mode or exposes private mind/UID.
- Regression tests after integration: `tests/test_full_playable_slice.tscn` 45/45, `tests/test_character_editor_ui.tscn` 55/55, `tests/test_character_network_panel.gd` 24/24, `tests/test_host_character_editor.tscn` 10/10, `tests/test_multiplayer.tscn` 67/67 (two test-intent unauthorized RPCs logged expected rejections), `tests/test_network_editor_live_enet.gd` 56/56, `tests/test_body_morphs.tscn` 62/62, Godot syntax 60/60.

## Explicit limitations: animation visuals ≠ realistic biomechanics

**The new in-game parts are procedural low-detail meshes located at real Blender anatomical reference coordinates**, NOT the original Blender sculpted 201 bone meshes / all its 72 process surfaces / watertight fat shell vertices. The latter remain in Blender's separate `.blend` and `.glb` model library. There was no direct binary GLB bridge between the disconnected Blender and Godot Space; using the **true authored reference rest geometry** to drive lighter in-game cylinders/ellipsoids is the first reliable visual integration.

Every anatomy render part follows the nearest relevant one of **17 existing animation driver bones** using `BoneAttachment3D`; 194 distinct anatomical bones are **not** independent dynamic game-skeleton joints. The 60 muscles are **single-anchor tubes**; they don't stretch anatomically across multiple joints, contract or transmit torque. The 60 cartilages and six fat volumes are ellipsoidal **visual proxies**, not realistic deformable soft tissues. Layer collision/thermal transfer/physiology and full 3D Elmer FE based on the original character mesh are **not** active in Godot and should not be claimed.

This is **client-local visual debugging**, not a multiplayer authorization change. `CharacterData`/saved snapshots remain identity/body/clothing/mind separate. The source anatomy file includes **no private account or user ID**, so it can be loaded by all game clients independently. Models lazy load only when requested; the normal player experience remains unchanged and performance cost is confined to the explicitly selected anatomical view.

2. Retarget the 194-bone Blender rig to 17 canonical gameplay bones, but **separate articulation of real individual finger/neck/vertebral joints** requires a new hierarchical anatomical animation/physics rig. At a minimum bridge between two animation attachment nodes across each muscle with nonlinear cross-joint skinning.
3. Add optional 3D diagnostic overlay for **actual Elmer 3D flat two-material slab** separately from the full human character; never map slab temperature falsely onto human body. For physically meaningful anatomy, generate real conforming finite-element body meshes and validate perfusion/heat, inverse kinematics and collision.
4. Comprehensive frame-captured graphical QA (the headless connector cannot reliably render `SubViewport` screenshot in the current setup), morph/pose stress test and performance LOD on mobile. Current scene tests validate **actual object transforms and GPU mesh resources**, not a clinical or production-ready physical simulation.

## How to see the feature in-game
Launch the playable Life Simulator in Godot with assets/visuals enabled. Select an existing character and click **Anatomie: Vypnuto** (Anatomy: Off) in the right-side HUD. The anatomical layers cycle over that **same in-world character**. The character creator/editor also offers the `Anatomie:` dropdown beneath the hand gesture controls. Switching back to `Vypnuto` restores the original clothing and visible body. All characters default to normal appearance.
